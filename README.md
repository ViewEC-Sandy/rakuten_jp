# Japan EC Dashboard V10.3

V10.3 以 V10.1 為基礎，整合 V10.2 的趨勢比較重構，並加入管理者分析與匯出功能。

## 主要更新

- 營收趨勢改為同期月份／季度／年度對齊，不再把不同年份放在不同 X 軸位置。
- 自動模式：只顯示本期或比較期實際有資料的月份／季度。
- 圖例顯示實際年份；缺少資料使用 null，不以 0 補值。
- 圖表粒度可切換：月、季、年。
- KPI 卡片支援點擊鑽取至平台或商品分析頁。
- 商品銷售排行擴充為 Top 20。
- 新增專案營收 Top 10 橫條圖。
- 新增每日營收熱力圖。
- 新增目前查詢結果 CSV 匯出。
- 新增瀏覽器列印／另存 PDF。
- 保留 V10.1：Rakuten 銷售額扣除「店舗発行クーポン利用額」。

## 部署

將所有檔案上傳至 GitHub Pages 專案，並確認 `firebase-config.js` 已填入正確 Firebase 設定。

## V10.3.1 修正
- 樂天廣告 CSV 的「日付」現在支援月份格式：`2025年01月`、`2025/01`、`2025-01`。
- 月份格式會以該月 1 日作為內部日期，並仍依月份彙總，不影響月報數值。

## V10.3.2 匯入引擎修正
- 移除逐列 `Promise.all(getDoc())` 的重複檢查，避免 `Too many outstanding requests`。
- 重複資料改為每個 collection 一次讀取文件 ID，再於瀏覽器記憶體中比對。
- Firestore 寫入改為每批 400 筆，依序提交，不同批次不並行。
- 批次提交遇到資源耗盡或暫時性服務錯誤時，採指數退避重試。
- 銷售、樂天廣告、商品分析匯入皆顯示即時筆數與百分比進度。

## V10.3.4 更新：商品分析 CSV 自動辨識表頭
- 商品分析 CSV 可直接上傳樂天原始下載檔。
- 系統會自動搜尋包含「商品ID／商品番号／商品管理番号（商品URL）／商品コード」等欄位的列作為真正表頭。
- 例如真正表頭在第 7 列時，會自動略過前 6 列說明資料，從第 8 列開始匯入。
- 同時新增「商品ID」欄位名稱支援。


## V10.3.4 修正
- 商品分析 CSV 遇到單獨或不完整的雙引號時，不再因 `Trailing quote on quoted field is malformed` 中止。
- 系統會保留可解析資料，並在匯入狀態顯示略過的引號格式警告數量。


## V10.3.6 修正
- 商品分析 CSV 的商品番号若實際上是商品管理番号，會自動改以商品管理番号對應商品主檔。
- 同一商品管理番号對應多個規格商品時，中文商品名會合併顯示，避免顯示「未對應」。


## V10.3.9
- 商品銷售排行改用商品番号或商品管理番号對應中文品名。
- 營運總覽營收依平台＋注文番号去重，避免歷史重複匯入造成倍增。
- Rakuten 訂單營收公式維持：商品合計金額＋送料合計－店舗発行クーポン利用額。


## V10.3.9 更新
- 樂天廣告分析與商品分析改為「開始月份／結束月份」區間篩選。
- 上方開始日期與結束日期按下套用或重新整理時，會同步更新兩頁的月份區間。
- 可跨月、跨年度查看與匯出報表。


## Enterprise V11 Unified Data Engine
- 營收 KPI、營收趨勢、平台占比、日曆熱圖與專案排行改用同一套訂單營收引擎。
- 同一平台＋訂單編號只取最新匯入版本，避免歷史版本重複或舊公式污染報表。
- 商品主檔比對支援商品番号、商品管理番号、大小寫／空白差異與多規格前綴。
- 商品銷售排行改用統一商品對應引擎，自動帶入中文商品名。


## V11.0.2 商品欄位規則
- 商品番号：同一商品不同變體的 SKU，商品主檔唯一 ID。
- 商品管理番号：商品編號，可對應多個商品番号。
- 商品主檔已移除日文商品名欄位。
- 商品跨平台：先商品番号，找不到再商品管理番号。
- 樂天廣告分析：先商品管理番号，找不到再商品番号。
- 商品分析：先商品番号，找不到再商品管理番号。


## V11.1 Reset Edition
- 新增系統維護頁，可查看各資料集合筆數。
- 可清除指定資料或一鍵清空全部匯入資料，保留 users、角色與 Firebase Authentication。
- 新增商品索引重建、Dashboard 重新計算與商品對應健康檢查。
- 部署時請同步更新 firestore.rules，讓管理者可以刪除匯入紀錄。
